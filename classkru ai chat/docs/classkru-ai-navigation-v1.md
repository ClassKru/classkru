# ClassKru AI Navigation V1 (local prototype)

The capsule button in the authenticated ClassKru app opens a conversation panel. This is a new ClassKru assistant, separate from ClassKru Studio and Mini Lab V5.

The server endpoint `/api/ai/navigation` uses a deterministic mock by default. This local test clone has `.env.local` set to `CLASSKRU_AI_NAV_PROVIDER=openrouter` and `CLASSKRU_AI_NAV_MODEL=openai/gpt-6-luna`; add a server-only key to that file to enable calls. The generic `.env.example` remains on mock. OpenRouter requests use a strict JSON schema, a timeout, bounded history, and `data_collection: deny`. No live API test has been made yet because the local key is blank. The endpoint requires a Supabase teacher session and `CLASSKRU_AI_NAV_ENABLED=true`; the one-click local launcher enables the flag by default. Set it to `false` to disable the endpoint, or set it to `true` in the server environment when enabling the feature after deployment. In the browser, set `localStorage['classkru-ai-navigation-enabled']='0'` to disable the panel without changing the rest of ClassKru.

`briefs/` contains server-only versioned navigation prompts; only versions registered in its private registry are loadable. The existing ClassKru auth helper uses the same `isClassKruMediaDeveloper` check as Mini Lab to show developer controls. The API remains authoritative and verifies the account on every request. Version changes begin a new in-memory conversation. `assets/classkru-ai-actions.json` is the shared allowlist. The server validates AI responses against it; the browser validates them again and verifies a selected classroom belongs to `appState.classes` before invoking the existing `navigateToWebScreen` function. No action can write teacher data. The panel retains conversation while moving between app screens and clears it when a different teacher opens it. Highlighted elements are nonblocking and dismissible.

Only the current screen, an optional selected classroom ID, bounded conversation text, and the selected brief version are sent to the server; OpenRouter receives the message and bounded history when its provider is explicitly enabled. Student records, rosters, scores, and attendance are not included. Neither the server nor browser persists the conversation. Developer usage logs omit message text and user IDs.

To test locally, add the OpenRouter key to `.env.local`, launch `Open-ClassKru.cmd`, sign in, and use the ClassKru AI button. Use a Developer account already authorized for Mini Lab to show the Brief selector. Change `CLASSKRU_AI_NAV_PROVIDER` back to `mock` to keep requests local. Brief files are excluded from Vercel static deployment and included only in the three server functions that load them.

Run the ClassKru AI Chat checks from the project root with `node --test "classkru ai chat/tests/classkru-ai-navigation.test.cjs" "classkru ai chat/tests/classkru-ai-panel.test.cjs" "classkru ai chat/tests/classkru-ai-v2.test.cjs"`.
